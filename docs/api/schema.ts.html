schema.ts

Small, fast schema validation.

The strategy is valibot's: one tree-shakeable export per schema and action, schemas as plain data, and pipe for refinement. The internals differ:

  • Every schema and action is the same three-field object, kind, def, and run. There is no separate action type, so pipe is a loop over schemas, and every run call site loads from one object shape.
  • kind and def describe a schema as data. What each kind's def holds is written down in SchemaDefs.
  • run returns the output directly and reports failure by counting it in ctx.fails. Nothing is allocated per node on the success path.
  • Output is copy-on-write: a container returns its input when nothing in it changed, so a valid value with no defaults, transforms, or keys to drop comes back as the same object. Callers must not assume a fresh copy, and a changed subtree still shares its unchanged siblings with the input. Changed is as Object.is tells: a 0 made -0 is, a NaN kept is not.
  • Issue paths are built on unwind: a container adds its key to the issues its child added, so valid input never touches a path. A key is pushed, so a path is built innermost first and reversed once as parse or parse_or_throw returns it, and a failing parse takes time in proportion to the paths it returns.
  • Schemas with no options are constants (string, not string()).
  • Messages are derived from structured issues by format_issue, which is only bundled when used.
  • An issue names the type of the value that failed and never holds the value, so issues can be logged, serialized, and kept without the input.
  • A union tries its options, and is runs, in probe mode: failures are counted without building issues.

Import as a namespace: import * as s from '@fuzdev/fuz_schema/schema.ts'. The design is described at more length in docs/design.md.

Flavored<TValue, TName>

type (TValue & Flavor<TName>) | (TValue & (Extract<TValue, null | undefined>))

import type {Flavored} from '@fuzdev/fuz_schema/schema.js';

Loose nominal typing. A plain value of the base type is assignable to the flavored type, so producing one needs no cast or parse, but two different flavors of the same base type are not assignable to each other. Good for values like ids and units, where mixing them up is the bug to prevent.

type Email = Flavored<string, 'Email'>; type Address = Flavored<string, 'Address'>; const email: Email = 'a@b.c'; // ok const address: Address = email; // error!

Flavors compose: a flavor of a flavored type is a narrower flavor, assignable to the one it flavors and not the reverse, as a brand of a brand is.

type WorkEmail = Flavored<Email, 'WorkEmail'>; const work: WorkEmail = 'a@b.c'; // ok const e: Email = work; // ok const w: WorkEmail = email; // error!

null and undefined pass through unmarked: Flavored<string | null, 'Email'> is the flavored string or null.

Of a type parameter whose constraint rules out null and undefined, as T extends string and T extends {} do, two flavors assign to each other. Generic code that keeps them apart flavors the constraint and intersects it with the parameter, which a plain T still assigns to:

// compiles: the two flavors of `T` mix const f = <T extends string>(x: Flavored<T, 'UserId'>): Flavored<T, 'PostId'> => x; // error! const g = <T extends string>( x: T & Flavored<string, 'UserId'> ): T & Flavored<string, 'PostId'> => x;

Formats an issue as format_issue does, with the value that failed in place of its type where get_issue_value(issue, input) finds it and it is a string, a number, or a boolean: kind: expected "function" | "variable", received "funtion".

  • A string is quoted as JSON, so a \n or \r can't add a line, and only its first 32 code units are written, with … after the closing quote when it has more. get_issue_value

schema.ts view source

(issue: SchemaIssue, input: unknown): { ok: true; value: unknown; } | { ok: false; } import {get_issue_value} from '@fuzdev/fuz_schema/schema.js';

Reads the value issue is about out of input, the value that was parsed, by following issue.path. It refuses where it would have to guess:

  • when the path leads through something that isn't an object or array
  • when what it finds is not of the type the issue received

Only own keys are read. A key that is missing reads as undefined, which is what the schema saw, so a missing required key is found with the value undefined. An inherited value is never returned.

The check is by type name, so it can't tell a value from another of the same type. Where an earlier step of a pipe replaced the value with one of its own type (a transform, or a container that applied a default or dropped a key) the issue is about the replacement, and what is returned is the input's value at that path.

memo_union
#

schema.ts view source

<const T extends ReadonlyArray<Schema>>(options: T): UnionSchema<T> import {memo_union} from '@fuzdev/fuz_schema/schema.js';

A union that keeps, for one parse, what it gave for each object or array it is probed with, and gives that back when it is probed with the same one again. A recursive union whose options walk a node's children before an entry rules them out takes time exponential in the input's depth, as each option walks them again at every level; this one walks them once, so the time is linear. Its kind and def are union's, and so are its verdicts and its issues: every reader of a schema, to_schema_json included, takes it as a union.

Use it where two options could take the same object or array and reach a lazy without a literal entry telling them apart first, as in lazy(() => memo_union([object({args: array(Node), op: literal('a')}), ...])). variant is the cheaper way out when the options have a literal discriminator, and so is putting first in each option the literal entries that tell the options apart. The memo is in the union that tries the options again, so on a chain of such unions each link is a memo_union, and where an option reads into another recursive union, as M in L = lazy(() => memo_union([object({x: array(L), t: literal('a')}), loose_object({x: array(M)})])), that union is one too. The memo is by the object: a step before it that returns a new object, as a transform that copies does, leaves it nothing to find, so such a step goes inside an option.

It keeps only what it gives while probing, which is how a union runs its options and how is runs: a union that is itself not probed runs as union does, and what its options hold is probed. What it keeps assumes the answer on an object depends on the object alone, which a getter, a Proxy, or a check with state can break. Where one does, is and parse can differ, as only probing reads the memo: is probes everything, and parse probes only what a union holds. Where a value comes back from the memo:

  • a transform, a check, or a with_default_fn's make beneath the union is not run again for an object the union is probed with again, by another option or where the input holds it twice, where under union it runs each time
  • an input that holds the same object twice gets the same output object in both places
  • a cyclic input still recurses until the stack runs out, as with union

The memo is a WeakMap for each parse, from each object or array probed to what came back, held in a WeakMap by the parse's context and dropped with it, so nothing of one parse reaches another. A context is one parse: a SchemaContext run again keeps its memo, which answers for an object it kept, changed since or not. Each probe of an object or an array looks it up, which costs a union that walks nothing again, and a parse that probes one allocates the map.

So a missing key matches only where an option lets its key be missing, as an optional does and an unknown doesn't, and with none it fails as any other value does, with the union's issue. UnknownSchema import {unknown} from '@fuzdev/fuz_schema/schema.js';

Accepts anything.

As an object entry it needs its key: undefined at a key the object has, own or inherited, is accepted, and a key that is missing fails as a missing_key. Write optional(unknown) to let the key be missing.

It tells the two apart by the object and key the object schema hands it, which reach it as the entry itself and through flavor, brand, message, nullable, lazy, an option of a union, and the first schema of a pipe. Anywhere else it is told nothing of a key and accepts undefined: at the top level, as an array's item, as a record's value, and as a step of a pipe after the first. Under a union whose first option to match a missing key after it fills the key in, as a with_default does, the key is optional, and it accepts the undefined, see union.

Fails a string that isn't a UUID of RFC 9562: five groups of hex digits, 8-4-4-4-12, with a version from 1 to 8 and the RFC's variant, or the nil or the max UUID. Either case of hex digit passes, and the output is the string as given. Fails any value that isn't a string, where regex would convert it. In a pipe its output is the type of the step before it.

VoidSchema import {void} from '@fuzdev/fuz_schema/schema.js';

Matches undefined, typed void in and out, so a function whose parameter is typed from it can be called with no argument: (input: Infer<typeof s.void>) => ... is called as f().

It is literal(undefined) in all but its types: its kind is 'literal' and its def is undefined, so every reader of a schema takes it as that literal, to_schema_json and to_json_schema refusing it as they refuse literal(undefined). As an object entry it needs its key, as that literal does: write optional(s.void) to let the key be missing.

Exported as void, a reserved word, so it is read as s.void through a namespace import.

<T extends Schema>(schema: T, value: SchemaDefaultOutput<T>): WithDefaultSchema<T> import {with_default} from '@fuzdev/fuz_schema/schema.js';

Replaces undefined with value. As an object entry it makes the key optional in the input and required in the output.

value is not validated, and is returned as it is: every parse that fills it in gives the same object, so an array or an object changed by one consumer is changed for every other. with_default_fn makes a new one each time.

schema is never given undefined, which value replaces, so an optional it holds never gives one: with_default(optional(string), 'd') outputs a string, and so does nullable(optional(string)), with its null. Any other schema keeps its output type, undefined and all, as one can give undefined for a value that isn't, as a transform can.

<T extends Schema>(schema: T, make: () => SchemaDefaultOutput<T>): WithDefaultFnSchema<T> import {with_default_fn} from '@fuzdev/fuz_schema/schema.js';

Replaces undefined with what make returns, called with no arguments once for each value it fills in. As an object entry it makes the key optional in the input and required in the output, as with_default does.

What make returns is not validated, as with with_default, and as in Zod. It is for a default that must be new on every parse, as a mutable array or object must, or that is computed when it is filled in: with_default_fn(s.array(s.string), () => []).

As an object entry whose key is missing, a make that returns undefined leaves the key out, as with_default with a value of undefined does. Over an optional, one typed to never return undefined makes an output that isn't, as with_default does for its value.
