schema_json.ts

Serializes a schema to the interchange form the Rust crate loads.

A node is {kind, def} as SchemaDefs has it, with def left out where it is undefined. A lazy holds a function there, so its def becomes a name, and the document is an envelope, {schema, defs}, whose defs are what the names stand for.

The crate refuses what it can't carry across, and so does this: it throws, naming the kind and the path, on anything Schema::from_json would reject, and on what the crate's parser would not read of the document itself: a string that is not well-formed Unicode, and nesting deeper than SCHEMA_JSON_MAX_DEPTH. A schema that serializes is one the crate loads. The reverse does not hold: schemas are counted through every lazy, so that a function making a new lazy each call ends, and a schema more than SCHEMA_JSON_MAX_DEPTH schemas deep that way is refused though its document would load.

It is a module of its own, so a bundle that serializes no schema carries none of it. It needs String.prototype.isWellFormed.
